# Changelog

Version numbers only change the last digit, and only when the owner says to make a proper release.
Everything in between is a nightly: a GitHub pre-release `bb1 nightly-<M>` (tag `nightly-<M>`, M = build − 25),
offered in the app on the Nightly channel (Settings → Updates). Up to build 25 they were called test builds (tag `build-<N>`).

## Nightlies since v0.0.0

- **Ready for the Windows client:** a client can now say which video codecs it decodes, and the host streams H.264 to one that can't decode HEVC (the new Windows client, apps/windows). Mac clients don't say, so they still get HEVC; the host switches back by itself when a Mac connects next. The repository is now a monorepo: the Mac app lives in apps/mac, with the same signature, bundle ID and update names as before.
- **"Updated" in the menu bar:** when bb1 comes back as the new build, the menu bar icon picks up where the progress bar left off: the full bar fades, a checkmark draws itself inside the little screen, holds for a moment, then fades into the usual bb1 mark (dimmed if this Mac isn't sharing or connected). About three seconds; it plays on any Mac that just updated, including ones updated from another Mac.
- **The menu bar finds new builds sooner:** opening the menu bar menu now checks GitHub (at most once a minute) and, if a new build turns up while the menu is open, "Update to …" appears right away. Before, a build published in the last few minutes only showed up after the 5-minute check or when the window came to the front.
- **Permissions fix themselves after a signature change:** macOS remembers Screen Recording and Accessibility by the app's signature, so after the move to the Developer ID the old entries looked switched on but didn't work (switching them off and on didn't help; removing one hid bb1 from the list). Now, the first time a build finds a permission missing, bb1 clears its own old entries (no admin password needed) and asks again, so bb1 shows up in System Settings ready to switch on. The Allow… buttons in Settings and the host menu do the same. It happens once per build at most, and never undoes a switch you just turned on.
- **Update progress in the menu bar:** while bb1 updates, the menu bar icon turns into a little screen that fills up from the left: one bar for the whole update, your other Macs first and then this one (hover for the percentage). It goes back to the bb1 mark when it's done. The Your Macs update pill shows the same number, and a Mac that finishes early no longer drops out of the count (the percentage could jump back).
- **Signed disk image:** installer layout no longer adds Finder metadata to the app after signing. The finished disk image is mounted and its app signature checked before publishing.
- **Builds on GitHub:** nightly and stable publishing now builds, signs and notarizes on a standard GitHub Apple Silicon runner. Both verified installer and updater files publish together; failed builds publish nothing. Local development and real Mac testing stay available. Update names, build counts and channels are preserved.

- **Getting ready for Apple signing:** this nightly is still signed with bb1's local certificate, but its updater also accepts bb1 signed with the owner's Apple Developer ID (team 5PLDN9BDV4). The next nightly is signed with the Developer ID and notarized by Apple. The build scripts now use the Developer ID when it's installed (hardened runtime, secure timestamp) and notarize and staple published builds and the disk image. They also no longer garble the keychain search list (an earlier version could merge its entries into one broken path).
- **Cleaner disk image:** the "bb1" wordmark in the top-left corner of the window is gone; the name stays in Finder's title bar (Finder always shows that bar).
- **Releases are written with a v:** "bb1 v0.0.1", in the app (Settings, menu bar, update pill) and on GitHub. The v0.0.0 release on GitHub is now titled "bb1 v0.0.0" too.
- **Test builds are now nightlies:** the next one is **bb1 nightly-1** (build 26), then nightly-2, … The update channel is Stable / Nightly, and bb1 calls itself "bb1 nightly-1" (or "bb1 v0.0.1" once it's a release) in Settings, the menu bar and the update pill. Your channel choice carries over, and copies on build 25 or older still find nightlies (updates still compare build numbers).
- **Fixed a crash with two streams open:** opening a second stream let go of the first stream's window controller while its window stayed up, and its keyboard hook still pointed at it; the next key press (here a window-tiling shortcut) crashed bb1. Now every open stream is kept, the keyboard hook is torn down with its window, and a hook can never outlive its owner.
- **Several streams at once:** connect to more than one Mac and each gets its own window (connecting to a Mac that's already open brings its window forward). The menu bar shows each stream with its own Stream options and Disconnect. A second window opens a little down and to the right of the first.
- **Window tiling works over a stream:** Globe-Control chords (🌐⌃← left half, 🌐⌃→ right half, 🌐⌃F fill, …) stay on this Mac, so you can put two streams side by side. ⌘⎋ and these are the only keys that don't go to the host.
- **Far-away Macs, part 2:** over a constrained path (a Tailscale relay, or loss) big frames go out at about 3× the bitrate in small steps instead of 300 Mbps bursts, which a relay drops. The client asks for a keyframe at most once per round trip (it asked every 300 ms, so on a 300 ms link it got several big keyframes in a row), and guesses the round trip from the handshake so this is right from the first frame. Against d1 (Johannesburg ↔ San Francisco, 300 ms): keyframe requests at connect 4 → 2, resends 9 asked / 3 recovered → 3 / 3, picture 185 ms behind (150 ms of it is the distance one way).
- **Far-away Macs (Tailscale relay):** a resend now has time to arrive from the other side of the world. The client waited only 250 ms for a missing packet and the host kept packets for 500 ms, so on a 300 ms relay every lost packet became a frozen picture plus a full keyframe. Now the client waits about 4× the round trip and the host keeps 2 s.
- **Quality adapts to the network:** when packets get lost, the host lowers the bitrate (down to 15%) and sends big frames in gentler bursts, then creeps back to full quality while nothing is lost. Over a Tailscale relay it starts at 40% instead of losing the first keyframe. The host log says when it changes ("sending at 70% of full quality").
- **Honest latency on Mac tiles:** "Online · N ms" is now the real round trip (a ping), not the time to download the screen picture, which over a far relay read 1300 ms for a 300 ms link. Needs the other Mac on this build; until then it shows the old number.
- **Your Macs:** the window opens bigger (three Macs across) and tiles keep their size, so a wider window fits more of them. The sharing tile is gone (Share This Mac is in Settings and the menu bar); with no other Macs you get a short note on what to do. The + lines up with the title. The ⋯ on a tile is a round Liquid Glass button (it was a squashed oval), and a tile that moves out from under the pointer no longer keeps showing it.
- **Rename a Mac:** ⋯ → Rename… gives one of your Macs your own name, on this Mac only (empty goes back to its own name). It's used on its tile and in the stream window.
- **Disconnecting just disconnects:** closing the stream (the red button or Disconnect) no longer opens the bb1 window, so with the window closed the Dock icon goes too. If the host ends the stream or it fails, the bb1 window still opens to say why.
- **Update channel:** Settings → Updates → Channel is Stable (releases only) or Test builds (test builds only), replacing "Include test builds". Macs that had test builds on stay on Test builds. Switching from Test builds to Stable doesn't go back to an older build; the next release replaces it.
- **No leftovers between connections:** each disconnect left the whole connection in memory (the decoder, its buffers, the last frame), because the decoder and the connection held on to each other. Both are freed now, along with the stream window's observers. Checked with `heap`: nothing of the stream is left after closing; the host side stays flat across many connections.
- **No leftovers between updates:** an update cut short (power off, crash) could leave `.bb1-update` with the previous bb1.app next to the app, or a downloaded zip in the temp folder; bb1 removes them on its next start. Old window-position settings from earlier builds are cleared.
- Logs now roll over while bb1 runs (at 20 MB the log becomes `<name>.old.log`), not only at start-up, so a Mac shared for weeks doesn't grow its log without limit.
- Menu bar menu: "Not connected" and "Connect…" are gone (Open bb1 does the same); the connection lines only appear while you're connected.
- **Control follows the pointer:** on the host's picture, keyboard and mouse go to the host; off it (title bar, black bars, outside the window) they're this Mac's again, and back on gives the host control again. No more releasing input by hand.
- **Simpler shortcuts:** the ⌃⌥⇧ chords are gone. ⌘⎋ gives control back without moving the pointer (the way out of full screen); the Stream menu uses normal Mac shortcuts while this Mac has control (⌃⌘F full screen, ⌘I stats).
- **Readable stream overlay:** stats and messages sit on a solid dark card with padding and a shadow, so they read over any picture; stats wrap between items, never inside one; warnings are amber.
- **Updating from the menu bar stays in the menu bar:** "Update to build N" updates your other Macs and then this one without opening the window, and the menu shows the progress. After any update bb1 comes back the way it was (window open, or just the menu bar icon). The menu always shows the version ("bb1 0.0.0 · build 21").
- Every menu bar item that does something has an icon (Settings and Quit had one, the rest didn't).

- **Faster recovery when macOS stops screen capture:** the host restarts capture as soon as macOS signals it (about 3 s sooner than before). On a nearly full disk, macOS's space clean-up (`replayd`) stops every screen capture; when that happens, or at connect, the client is told the host is low on disk space (under 5 GB free). Host notices on the stream now fade after 10 s, apart from "The host can't…" warnings.
- **Remove bb1 is gone from Settings** (turn off Open at login and drag bb1 to the Trash instead).
- A Mac too old to send its screen now says so on its tile instead of just "Online": "Online · update to see its screen", or for a bb1 from before updates, "Online · old bb1, update it there" (it has to be installed by hand once). Such a Mac is re-checked every 15 minutes, so once it's updated by hand its screen shows up without connecting to it first.
- **New Settings page:** five sections (Sharing, Who can connect, App, Updates, Help), each a short title and one line on the left with its settings grouped in one card on the right, divided by hairlines. Shorter wording, small buttons, and a segmented picker for the Dock icon instead of a macOS pop-up menu.
- **Header polish:** a taller title bar, so the header has room; the bb1 mark, gear, avatar and Settings' back button line up exactly with the window buttons (measured from them, not guessed); the gear is a true circle with no border (just a soft circle on hover); the right side mirrors the window buttons' inset; the back arrow is a proper chevron. Offline Macs' last screens are now properly greyed out (they rendered as black specks).
- **New Your Macs page (direction A):** each of your other Macs is a tile showing its actual screen, refreshed every few seconds while the window is open ("Online · 9 ms"); offline Macs show their last screen, greyed ("Offline · seen 2 h ago"). Click a tile to connect. This Mac is a dashed tile with the bb1 mark and the sharing switch. No sidebar: Settings is behind the gear, with a back button. The host sends the pictures over a quiet side connection that doesn't touch a stream (hosts need build 15+).
- Checking a host's build now happens at most every 5 minutes (it ran every 2 s while the window was open), and also for newly paired Macs.
- **Update pill:** a new build shows up by itself as a pill in the Your Macs header ("Update to build 13"). Click it to update; the pill shows the progress, then "Updated to build 13", which fades away after a few seconds. bb1 checks every 5 minutes and whenever you bring it to the front (no need for Check for Updates).
- **Installs from a disk image:** a `.dmg` whose window is the bb1 mark (half light, half graphite); an arc carries bb1 across the split into Applications. The zip stays for in-app updates.
- **No more install scripts:** bb1 sets itself up. Opened from the disk image or Downloads, it offers to move into Applications. A new copy quits older ones, points the login item at itself and puts the old `~/Applications` copy in the Trash. Turning on Share This Mac also turns on start at login (with restart after a crash). Settings → Remove bb1 takes it off the Mac. `install-host.sh` and `uninstall-host.sh` are gone.

## v0.0.0 — 2026-10-20 (first release)

Everything so far.

- **One app for both roles.** Share this Mac and/or connect to your other Macs. Parsec-style dashboard (Your Macs, Settings), menu bar icon, Dock icon options, keeps running in the menu bar.
- **Streaming:** native-resolution screen capture (ScreenCaptureKit), hardware HEVC in low-latency mode, 60 fps, UDP with packet resend on loss, ~10–15 ms capture-to-screen on a home network.
- **Control:** mouse, trackpad scrolling with momentum, keyboard including Cmd shortcuts (with Accessibility on the client). Input modes: keyboard & mouse, keyboard only, mouse only, view only. Release input with ⌃⌥⇧R.
- **This Mac's cursor by default:** instant, and it takes the host's shape (arrow, pointing hand, I-beam…).
- **Sound** from the host with an adaptive buffer. Silence isn't sent. Mute with ⌃⌥⇧M.
- **Clipboard** shared both ways (text and images). Password-manager copies are skipped.
- **Sign-in without keys:**
  - Tailscale (devices on your account are let in)
  - a one-time 6-digit pairing code
  - remembered pairings
  - the old pairing key is upgraded automatically
- **Away from home over Tailscale:** shows whether the route is direct or relayed.
- **Self-recovery:** watchdogs on every stage (capture, encoder, network, decoder, display), automatic reconnect, and a fault-injection test.
- **Logging:** both sides' per-second stats (including CPU and memory) in the host's log, plus stall, hitch and memory-pressure lines.
- **Stream options:** fullscreen, fill screen, scaling (fit / stretch / actual pixels).
- **Idle cost:** about 1% CPU on the client when the screen is still.
- **Caps Lock** on the client now works on the host: its state is synced, and the host's real Caps Lock follows it.
- Fixed: two cursors on first connect when using this Mac's cursor. The setting could arrive while capture was starting, and got lost.
- The host's capture-freeze check needs 3+ clicks or keys with no new frame for 4 s, so a single quiet click can't trigger it.
- The app version is shown in Settings → About and logged at startup.
- **Updates from inside the app:** bb1 checks GitHub every hour. When a newer build is out, a banner on Your Macs offers it; one click updates your other Macs that are behind (you see each one download, install, restart and come back on its card), then this Mac, which restarts into the new build. Settings → Updates shows the version and build, has Check for Updates, and "Include test builds". Downloads are only installed if they're signed with bb1's own certificate, so permissions carry over.
- Fixed: opening Settings froze the app (builds 6 and 7).
- **New look, matched to the icon:** flat, near-black greys (no gradients or shadows), white buttons and switches instead of system blue, and each Mac drawn with the bb1 mark on its screen (white when online, dim when offline or not shared).
